      How Paper Trail works
      
        
      
          
        
      
      
      
      
      
        
      
          
      Everything starts on this desk
      
          
      Documents you add are stored in a local folder on this machine — ./data unless the server was started with another path. Deleting a document removes its stored pages and files. There is no account and no permanent cloud copy.
      
        
      
        
      
          
      Hosted today, local tomorrow
      
          
      When GEMINI_API_KEY is set, adding page images can trigger a one-time transcription call (up to eight pages by default), and Analyze sends that document’s pages to Gemma 4 through the hosted Gemini API. Without a key it runs in demo mode with recorded sample answers and makes no external requests. The same adapter can point at a local OpenAI-compatible model later — the interface here does not change.
      
        
      
        
      
          
      The model reads. The code checks.
      
          
      Every extracted fact carries a page and a quote. The server checks each quote against the stored page text before you see it: ✓ means it matched, ! means it could not be verified and is shown anyway. Citations are never silently dropped.
      
        
      
        
      
          
      What leaves this machine
      
          
      The pages of documents you add or analyze, and only when hosted analysis is on. The counter in the header records every outbound model request, including retries. Demo mode sends nothing. Paper Trail has no telemetry, uses no CDN, and never returns an API key to the browser.
      
        
      
        
      Paper Trail helps you read mail. It is not legal, medical, or financial advice; confirm names, addresses, and deadlines on the original notice.
